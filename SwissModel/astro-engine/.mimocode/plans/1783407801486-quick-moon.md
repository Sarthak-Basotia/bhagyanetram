## BUGS (must fix)

### 1. D60 Shashtiamsa — Wrong Formula
**File**: `app/services/charts.py:49-51`

Current: `(s + part) % 12` — divides each rasi into 60 equal parts and maps linearly.

Standard Parashari (BPHS Ch.7): Seshamsha alternates based on sign parity:
- Odd rasi (Aries, Gemini, Leo, etc.): starts from the sign itself, alternates every 2 parts
- Even rasi (Taurus, Cancer, Virgo, etc.): starts from the 7th from the sign, alternates every 2 parts

**Fix**:
```python
if dcf == 60:
    part = int(d // (30 / 60))
    if s % 2 == 0:  # odd rasi (Aries=0 is odd sign, even index)
        return (2 * s + (part % 2) * 6) % 12
    else:
        return (2 * s + 6 - (part % 2) * 6) % 12
```

**Impact**: Every planet's D60 placement is currently wrong. D60 is used for advanced dasha timing and life-pattern analysis.

### 2. Panchak Threshold — Off by ~6.67°
**File**: `app/services/calendar_svc.py:78-79`

Current: `_moon_long(jd) >= 300.0` — this includes Shatabhisha padas 1-3.

Standard: Panchak starts at **Dhanishta 3rd pada = 306.67°** (i.e., `300 + 2 * (360/27/4)`). Only the last 2 padas of Dhanishta + all of Shatabhisha + Purva/Uttara Bhadrapada + Revati constitute Panchak.

Additionally, the comment says "Moon in Aquarius/Pisces" but the nakshatra-based definition is more precise — it should reference the specific nakshatras.

**Fix**: Change threshold to `306.6667` (Dhanishta 3rd pada start) and update the description string.

**Impact**: Panchak windows are reported ~2 days too long at the start.

### 3. Combustion — Moon Should Not Be "Combust"
**File**: `app/services/charts.py:111` (and similar in chandra_chart, transit_chart)

Current: `is_combust(name, p.longitude, sun_lon)` is called for all planets including Moon. Moon IS in `COMBUSTION_ORB` (12°), so Moon can be marked combust.

Standard: Moon's proximity to Sun is an **eclipse** condition, not combustion. Combustion (astangata) applies only to Mars, Mercury, Jupiter, Venus, Saturn. Moon has a separate "amavasya" or "eclipse" status. Many software mark Moon as combust, but the standard BPHS definition does not include Moon in combustion.

**Recommended**: Either remove Moon from `COMBUSTION_ORB` or add a separate `is_eclipse()` check and rename the field. At minimum, document this as a deliberate choice.

**Impact**: Minor — Moon marked combust when within 12° of Sun. Some users may find this confusing.

## ACCURACY GAPS (should fix)

### 4. No Moolatrikona Distinction in Dignity
**File**: `app/services/charts.py:69-81`, `app/core/constants.py:38-41`

Current: `dignity()` returns "own" for both regular own-sign and Moolatrikona placement. The comment says "moolatrikona/own" but they're not distinguished.

Standard: Moolatrikona (MT) is a stronger dignity than regular own-sign. Many yoga rules specifically require MT placement. Classical MT definitions:
- Sun: Leo 0°-20°
- Moon: Taurus 0°-3° (note: Moon's exaltation is also Taurus 3°, so MT overlaps)
- Mars: Aries 0°-12°
- Mercury: Virgo 0°-15° (note: Mercury's exaltation is also Virgo 15°)
- Jupiter: Sagittarius 0°-10°
- Venus: Libra 0°-15°
- Saturn: Aquarius 0°-20°

**Fix**: Add `MOOLATRIKONA` dict to constants.py with sign+degree ranges. Update `dignity()` to check degree within own sign for MT classification. Return "moolatrikona" as a separate state.

**Impact**: Chart output lacks precision for advanced analysis. Yogas requiring MT won't be correctly identified.

### 5. Exaltation Degree Not Checked
**File**: `app/services/charts.py:69-81`

Current: `dignity()` returns "exalted" if the planet is anywhere in the exaltation sign.

Standard: A planet is truly exalted only at its exact exaltation degree. At other degrees in the same sign, it's "in exaltation sign" but not "at exaltation point." Some traditions consider any placement in the exaltation sign as exalted; others require the specific degree.

**Recommended**: This is a known simplification. Add a `dignity_detail` field that includes degree-level precision: "exalted" (anywhere in sign), "at exaltation point" (at exact degree), "moolatrikona", "own", "friendly", "neutral", "enemy", "debilitated".

**Impact**: Minor for most users; important for precision-focused practitioners.

### 6. Missing Yoga Detection — README Overpromises
**File**: `app/services/yoga.py`

README says "Raj yoga detection (kendra-trikona, parivartana, gajakesari, dharma-karmadhipati)" and "extend services/yoga.py to reach the full 24."

Current implementation detects:
- Kendra-Trikona Raj Yoga (conjunction, exchange, mutual aspect, one-way aspect)
- Yogakaraka (single planet lords both kendra and trikona)
- Gajakesari (Jupiter in kendra from Moon)
- Dharma-Karmadhipati (9th + 10th lord association)

Missing common yogas:
- **Chandra Yogas**: Sunapha, Anapha, Durudhura, Kemadruma, Vasumana (some in combinations.py)
- **Dhana Yogas**: 2nd/11th lord associations
- **Nabhasa Yogas**: Aerial, Dhwaja, Keelaka, etc.
- **Pancha Mahapurusha**: In combinations.py but not in yoga.py
- **Budha-Aditya**: In combinations.py but not in yoga.py

**Recommended**: Either implement more yogas or update README to list exactly what's detected.

**Impact**: Users expecting full yoga detection will be disappointed.

## STRUCTURAL IMPROVEMENTS

### 7. Dasha Date Precision
**File**: `app/services/dasha.py:24-26`

Current: `_fmt()` rounds to the nearest day by adding 12 hours.

Standard: Most Jyotish software reports dasha boundaries to the day, but some report to the minute. The current approach loses time precision.

**Recommended**: Add an optional `precision` parameter: "day" (current), "time" (includes HH:MM). Many users want to know the exact hour a dasha changes.

**Impact**: Minor — day-level is standard for most use cases.

---

### 8. Missing Panchak Details
**File**: `app/services/calendar_svc.py:77-79`

Current: Only checks if Moon longitude >= 300°.

Standard: Panchak has sub-types based on which day of the week it falls on:
- **Rog Panchak** (Monday)
- **Shool Panchak** (Tuesday) — with direction (East/West/North/South)
- **Raj Panchak** (Wednesday)
- **Mrityu Panchak** (Thursday)
- **Chor Panchak** (Friday/Saturday/Sunday)

Each has different remedies and severity.

**Recommended**: Add weekday-based sub-type to Panchak output.

**Impact**: Enriches Panchang output with actionable information.

---

### 9. Sade Sati — Missing Dhaiya/Sub-periods
**File**: `app/services/dosha.py:235-309`

Current: Reports Sade Sati phases (Rising/Peak/Setting) and Dhaiya (Saturn in 4th or 8th from Moon).

Standard: Sade Sati also has sub-phases based on Saturn's nakshatra transit within each sign. Additionally, "Ashtama Shani" (Saturn in 8th from Moon) is sometimes treated separately from Dhaiya.

**Recommended**: Add Saturn's nakshatra within each sign for finer phase resolution.

**Impact**: Enhancement for advanced users.
